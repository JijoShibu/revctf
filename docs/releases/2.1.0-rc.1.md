# RevCTF 2.1.0-rc.1

Release candidate under validation. It has not been published.

This release focuses on the four-report QA review: bounded static flag recovery,
accurate format routing, truthful diagnostics, and safe archive handling. All
candidates remain unverified. No remote challenge interaction is performed.

## Changes

- Reverse printable byte sequences and try all single-byte XOR keys in bounded chunks.
- Recover repeating-key XOR with periods 2–8 when a recognized/literal wrapper supplies
  sufficient constraints. This is not unrestricted key search or hash inversion.
- Keep unfamiliar decoded wrappers and show flag-like text before hash-like metadata.
- Add schema-versioned candidate evidence with stage attribution, capture locations,
  true binary offsets where established, and recovered key bytes.
- Correct advice that previously referred to high-confidence candidates when none existed.
- Recognize Python source and WASM, skip inapplicable native stages, and provide
  bounded Python AST review without importing or executing the source.
- Reject ZIP/tar traversal, links, special files and declared expansion/member excess;
  enforce actual streamed extraction bytes. Disclose selected-payload/depth omissions.
- Diagnose Ghidra import failure before reporting secondary missing heap verification.
- Bound custom-pattern validation and Docker availability checks; disable container IPC.
- Warn about inactive prompt/debug switches and explicit unisolated execution.

## Compatibility and limits

Existing four-field flag records remain intact; JSON evidence is additive. Unknown
locations are null. A capture byte offset must not be interpreted as a binary offset.
The recovery pass has a 16 MiB input window, 20-second time budget and 1024-occurrence
budget. Exhaustion marks analysis partial and preserves available evidence.

Python/WASM expected format mismatches now skip instead of causing spurious native
analysis failures. Unknown raw data no longer receives a native disassembly claim.
Safe automatic extraction currently supports ZIP and tar only. It follows one selected
payload; multiple members are not claimed as a complete batch scan. Unsupported
formats, unexamined members and depth limits are disclosed. The existing per-file
output cap does not constitute an aggregate run disk quota.

The tested installation profile remains Kali amd64/Python 3.14, Ghidra 12.1.4 and
the locked dependency set. Ubuntu controlled tests do not validate this complete profile.

## Validation and promotion

See `docs/qa-2.1-validation.md` and `docs/release-evidence.json`. Pending checks must
not be presented as passed. Publication requires current-runtime Kali, Docker,
Ghidra, installation, offline, cleanup and rollback evidence plus hosted checks.
Do not reuse 2.0.0 evidence to satisfy these gates. Published tags are immutable.

Symbolic solving, batch scheduling, persistent logging, caching and broad WASM
decompilation are later work. Ghost Core remains beginner content; its redesign is
separate from RevCTF. Roll back by selecting the preserved 2.0.0 checkout and its
verified tool profile, using a new report directory.

Provenance locations distinguish the original input from a derived/unpacked payload.
A derived payload offset never claims a location inside the original archive.
Custom flag-pattern matching also has a ten-second budget per transformed capture;
a reached budget marks the search partial while built-in matching continues.
